Installation

No build tools are required.

  1. Unzip yardshield.zip.
  2. Open index.html in any modern browser. It forwards to pages/index.html.
  3. To publish, upload the whole folder to any static host (Netlify, Vercel, GitHub Pages, S3, cPanel). Point your domain at the folder; optionally set /pages as the web root.

Bootstrap 5.3.3, Bootstrap Icons 1.11.3 and Chart.js 4.4.1 are bundled in assets/vendor, so pages work offline and from file://. Only the two Google Fonts load from the internet; without them the system font is used.

Optional local server: npx serve . or python3 -m http.server inside the folder.

Colors

All colors live in :root at the top of assets/css/style.css. Components only read tokens, so changing a token restyles the whole site.

--ys-primary
#1e7b3c
--ys-secondary
#14532d
--ys-accent
#f2a30f
--ys-bg
#f6f8f3
:root {
  --ys-primary: #1e7b3c;        /* buttons, links, success  */
  --ys-primary-strong: #16692f; /* hover                    */
  --ys-secondary: #14532d;      /* trust surfaces, focus    */
  --ys-accent: #f2a30f;         /* primary CTAs             */
  --ys-accent-ink: #1b1f1d;     /* text on accent           */
}

Also update --bs-primary-rgb to the RGB of your primary color, and the matching values in dark-mode.css. All default pairs meet WCAG AA (4.5:1 or better); re-check contrast for your own colors.

Fonts

Two families: Bricolage Grotesque (headings) and Figtree (body). To change them:

  1. Replace the Google Fonts URL (search fonts.googleapis.com in /pages).
  2. Update --ys-font-heading and --ys-font-body in style.css (and in rtl.css if you use RTL).

See assets/fonts/README.md to self-host.

Content & images

  • Brand name: find & replace YardShield. The logo is an inline SVG in the header/footer (.brand-mark) and assets/images/favicon.svg.
  • Domain: replace yardshield.example in canonical tags, Open Graph, JSON-LD, sitemap.xml and robots.txt.
  • Photos: the template uses real photography from Unsplash (free for commercial use, no attribution required). Each image is a <picture> with responsive WebP sources (480/800/1200 px), a JPG fallback and explicit width/height, so there is no layout shift. Unsplash crops each photo to its slot automatically.
  • Offline fallback: if a photo can’t load (no internet), the page swaps in the matching illustration from assets/images.
  • Using your own photos: the cleanest route is to save them as assets/images/<name>.webp and .jpg (names listed below) and remove the photo URLs from the HTML, so nothing depends on a third-party host. Recommended sizes: 1200×750 for cards and sections, 1200×900 for the hero, 1200×1400 for the login/register side panels, 480×480 for team portraits.
  • Prices: plan cards use data-monthly and data-annual attributes (annual = per-month price when billed yearly).
  • Service area: edit YS.zip.SERVICE_PREFIXES in main.js or replace it with an API call.

Dark mode & RTL

Dark mode follows the visitor’s OS setting until they press the moon/sun toggle ([data-theme-toggle]). The choice is saved in localStorage. An inline script in <head> applies it before first paint. Charts re-render on the ys:themechange event.

RTL: the RTL button ([data-dir-toggle]) previews the mirrored layout by setting dir="rtl" and swapping in bootstrap.rtl.min.css. For a real Arabic or Hebrew site set <html lang="ar" dir="rtl"> and link the RTL Bootstrap file directly. Custom CSS uses logical properties, so it mirrors automatically.

Components

Reusable classes, used consistently across pages:

badge-softbadge-tealbadge-amberbadge-dangerbadge-muted
  • .card + .card-hover, .icon-circle (.sm, .teal, .amber), .check-list, .pest-chip
  • .table-stack — tables become cards under 640px; give each <td> a data-label.
  • [data-skeleton] — wrap a .skeleton-view and a .real-view; call YSD.skeletons.done(el) when data arrives.
  • Spacing tokens --space-1 (8px) to --space-12 (96px). Breakpoints in custom CSS: <640, 640–1023, 1024–1279, ≥1280. Bootstrap’s own grid and navbar collapse at 992px.

Forms & validation

Add class="needs-validation" novalidate to a form and an empty .invalid-feedback after each field. YS.forms validates on blur and submit, writes a clear message, sets aria-invalid/aria-describedby and focuses the first error.

  • Custom messages: data-msg-required, data-msg-email, data-msg-pattern.
  • Confirmation fields: data-match="#password".
  • After success: data-toast="…" shows a toast, data-redirect="page.html" navigates, a .form-success block is revealed.
  • If the form has an http(s) action, it is posted with fetch (works with Formspree and similar).

SEO, performance & accessibility

  • Unique titles and descriptions, canonical URLs, Open Graph and Twitter tags on every page.
  • JSON-LD: LocalBusiness + FAQPage (home), ItemList of Service (services), Service with Offers (service details, pricing), BlogPosting (article).
  • sitemap.xml lists public pages; robots.txt excludes the portal.
  • Performance: WebP images with fallbacks, explicit dimensions, lazy-loading below the fold, fetchpriority="high" on the hero, deferred scripts, no render-blocking JS. For best scores, self-host fonts and serve with compression and caching.
  • Accessibility (WCAG 2.1 AA): skip link, visible focus rings, 44px touch targets, labelled controls, ARIA live regions for dynamic results, keyboard-operable calendar (arrow keys), charts with text alternatives, prefers-reduced-motion support.

Browser support

Latest two versions of Chrome, Edge, Firefox and Safari (desktop and iOS/Android). Uses CSS color-mix() and aspect-ratio; older browsers degrade gracefully.
